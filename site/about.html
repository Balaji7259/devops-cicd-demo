The deployment path

What happens after a push

Nine things happen between git push and a visitor seeing the new page. Each one runs in a different place, which is why the “where” column matters when something breaks.

  1. Commit is pushed — your Windows machine uploads the change to GitHub.
  2. Change is detected — GitHub matches the push against the workflow file and queues a run.
  3. Code is tested — a temporary Ubuntu runner checks the required files exist.
  4. Image is built — docker build executes the Dockerfile on that runner.
  5. Image is pushed — the layers are uploaded to Amazon ECR, tagged with the commit SHA.
  6. Server is contacted — the runner opens an SSH session to your EC2 instance.
  7. Image is pulled — EC2 downloads that exact tag from ECR.
  8. Container is replaced — the old container is removed and a new one starts from the new image.
  9. Nginx serves it — port 80 answers on the instance’s public address.
